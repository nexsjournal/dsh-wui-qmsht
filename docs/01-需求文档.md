# 《清明上河图·众生图鉴》H5 — 项目需求文档（PRD）

> 版本 v1.0（评审稿） | 状态：待确认
> 项目名称：清明上河图 · 众生图鉴（暂名，可改）
> 形态：移动端优先的单页 H5（浏览器直接打开，无 App 壳）

---

## 1. 项目背景与目标

《清明上河图》（传张择端，北宋，绢本 4206×1733px 数字化长卷）描绘了北宋都城汴京（今开封）清明时节的市井生活，画面含人物约 1600+ 名、船只 20 余艘、牲畜 60 余头、车轿 30 余辆。

本项目将该长卷转化为**可交互的角色图鉴 H5**：用户自由漫游长卷画面，点击任意人物打开其「角色详情」，并通过「人物关系图谱」看到由画面位置关系推演出的世界观与关系网。

### 产品目标
| # | 目标 | 衡量方式 |
|---|------|----------|
| G1 | 首屏可交互时间 ≤ 3s（4G） | Lighthouse / 真机 | ✅ Lighthouse 移动4G：LCP 2.9s、TBT 0ms（2026-08-25 实测，见 04 文档验收记录） |
| G2 | 漫游、缩放、切换 Tab 全程流畅（≥50fps，中端机） | 真机实测 | ⏳ headless 全链路零错误；真机帧率待用户实测 |
| G3 | 角色详情与关系图谱完整可用，古风体验一致 | 走查清单 | ✅ 31 角色 + 38 关系边 + 世界书，冒烟全链路通过 |
| G4 | 全尺寸响应式：手机竖屏 / 手机横屏 / 平板 / 桌面 | 多端走查 | ✅ 1280×860 / 390×844 双端走查通过 |

### 非目标（本期不做）
- 不登录、无账号体系、无支付
- 不做 PWA 离线包（预留结构）
- 不做角色语音/视频
- 不做小程序端（目录名遗留，本项目按纯 H5 实现；如需多端另行立项）

## 2. 名词定义

| 名词 | 定义 |
|------|------|
| 长卷 / 画布 | `assets/清明上河图.jpg` 的全画面坐标系（以 4206×1733 为 100%） |
| 角色（人物） | 画布上一个可点击的人物锚点（hotspot），绑定一份角色档案 JSON |
| 角色详情 | 角色档案的全屏页面：立绘/头像、身份、背景故事、人物设定、关系列表 |
| 图谱 | 以角色为节点、以关系为连线的关系网络视图（可拖拽/缩放） |
| 关系 | 两个角色之间由「画面位置 + 场景语义」推演出的关系（同船、交易、雇佣、亲眷、围观……） |
| 世界 | 统摄全部角色设定的世界观总纲（时代、地点、社会结构、势力分组） |

## 3. 用户与核心场景

**目标用户**：对中国传统文化/古风感兴趣的泛用户（文旅、文博、国风爱好者），无前置知识。

**核心场景**
1. **闲逛模式**：打开 H5 → 看到巨幅长卷 → 手指拖拽漫游 → 放大细看 → 被某个人物吸引 → 点击。
2. **考据模式**：点开角色详情 → 读完身份与背景 → 点关系链跳去认识相关人 → 顺藤摸瓜逛遍一整条人物线。
3. **图谱模式**：底部切到「图鉴图谱」Tab → 俯瞰全体角色关系连线 → 点某个节点打开详情。
4. **氛围模式**：全程背景音乐（古风纯乐）+ 宣纸/墨韵视觉，营造「展卷品画」的仪式感。

## 5. 角色数据需求（数据即内容）

- 首批角色规模：**24~32 个有名有姓的核心角色**（覆盖全卷各段，保证每个可见区域都有可点角色），每个角色一条 JSON 档案。
- 档案字段（详见 04 开发文档数据结构）：`id / 名号 / 身份 / 阵营 / 坐标(归一化) / 简介 / 背景故事 / 设定键值 / 关系[] / 立绘 / 场景裁剪参数`。
- 关系由开发阶段**依据画面位置与场景语义人工推演**并写入数据（例如：桥上拥挤人群中「拉车人—货主—围观者」构成一条「赶考赴京」支线；虹桥下「纤夫—船工—酒保—买酒客」构成「渡口」支线）。所有关系需在文档中可追溯（05 文档含推演依据表）。
- 世界观：以北宋汴京为基底做**轻度架空**（人物姓名虚构、事件可演绎，历史骨架不变：清明时节、汴河漕运、虹桥拥堵、市井百业），形成「一条漕船引发的汴京一日」主线，串联全部角色（详见 05 文档）。

## 6. 交互与体验要求（古风基调）

- **视觉母题**：宣纸、水墨、朱砂印章、篆/隶点缀字、绢本色调（米白+赭石+黛青+朱砂）。
- **动效基调**：慢而柔，带「墨晕开」质感（展开/淡入用模糊+缩放），切换有「翻页/展卷」仪式感；所有动效 ≤400ms（除开场 2.5s）。
- **字体**：标题用书法感字体（思源宋体 Heavy + 行楷点缀；注意 Web 字体子集化、体积控制）。
- **声音**：古风纯乐 BGM（古琴/箫/鼓，无版权风险，来源见技术栈文档）+ 轻 UI 音效（P2：点击「印章」声、翻页声）。
- **文案语气**：半文半白，人物简介像「人物小传」，避免现代梗。

## 8. 性能需求（硬性）

| ID | 指标 |
|----|------|
| P0-1 | 首屏（开场结束+画卷可见+可拖拽）≤ 3s @4G；JS+CSS+首图 ≤ 1.5MB |
| P0-2 | 原图 10.6MB 不得整图直出：必须多档降采样 + 按缩放级别懒加载高清（方案见 04 文档） |
| P0-3 | 平移/缩放帧率 ≥50fps（中端 Android，i6 级）；拖拽期间不触发布局重排（只动 transform） |
| P0-4 | 24~32 个锚点 + 图谱 30 节点力导向：同屏渲染开销 ≤ 1 帧预算；图谱静态化（布局完成后停止 tick） |
| P1-1 | 角色立绘全部懒加载（详情打开时才请求，WebP ≤ 150KB/张） |
| P1-2 | 字体、音乐（首 30s）均为懒加载；Lighthouse Performance ≥ 85 |

## 9. 兼容与运行环境

- 浏览器：iOS Safari ≥ 15、Android Chrome ≥ 100（WebView 同）、桌面 Chrome/Edge/Safari 最新版；不兼容 IE。
- 输入：触摸（单指拖拽/双指捏合/双击）+ 鼠标（拖拽/滚轮/双指触控板）+ 键盘（←→↑↓ 平移、+/- 缩放、Esc 关闭详情，P1）。
- 视口：`viewport-fit=cover`，适配刘海屏安全区。
- 网络：无后端、无接口，全部静态资源 + 本地 JSON；可直接拖拽进浏览器打开（file:// 或任意静态服务器）。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 原图过大（10.6MB / 4206px） | 卡顿、流量 | 三档 WebP（全览/中/高清局部）+ 视口内懒加载；详见 04 |
| 长卷双指缩放+惯性在低端机掉帧 | 体验差 | 纯 transform + will-change 分层；降级策略（低端机关闭惯性） |
| 30 个 AI 立绘风格不一致 | 视觉割裂 | 统一 prompt 模板 + 参考图锚定；先用 6 张试风格再批量 |
| 角色位置标注主观 | 用户质疑「这不是那个点的人」 | 锚点带「据画面考据」文案弱化绝对性；05 文档附推演表 |
| 音乐版权 | 法律风险 | 仅用 CC0/自制/生成音频，见 03 文档 |
