# 《清明上河图·众生图鉴》H5 — GitHub 关联项目调研与延展思路

> 版本 v1.0 | 调研时间：2026-08-26 | 方法：GitHub 全局仓库搜索（关键词：清明上河图 / 清明上河 / qingming scroll / along the river during the qingming / qmsht / 上河 交互 / 数字长卷 等），人工过滤垃圾仓库后共得 15+ 有效项目

## 0. 一句话结论

- GitHub 上同题材项目以 **3D 观展类**（Three.js 展卷/漫游）和 **学生课设类** 为主，**没有**与本项目同形态（2D 长卷 + 角色图鉴 + 关系图谱）的成熟开源项目 —— 我们的「众生图鉴」定位是差异化的，延展方向应借鉴他人的**交互/玩法/性能技巧**，而非追赶 3D。
- 最值得借鉴的三个点：**展卷物理动效**（Dolio1000）、**任务化玩法**（juicyzhou 汴京漫游）、**声画联动与自动巡览**（LittleWhitechun / pakho2433）。

## 2. 重点项目拆解

### 2.1 Dolio1000 — 3D 展卷（最值得抄「交互手感」）

- **展卷物理**：左侧卷轴半径随展开进度按平方根公式收缩，卷轴高度与画面平面相切 —— 真实卷轴感的关键公式，可直接移植到 2D 开场动画。
- **渐进加载**：首屏只载 2–5KB 占位图，滚动时按需预取 600–860KB 高清分片，下载完异步解码、画面静止时再换入 GPU —— 与我们的三档图层调度同源思路，其「静止时换图」细节可借鉴。
- **手感**：指数衰减 Lerp（系数 0.02）惯性滚动 + 双击对焦近景；与我们自研 inertia 同族。
- **氛围**：Canvas 2D 宋词竖排下落动画（苏轼/辛弃疾/李清照/柳永），独立模块 `calligraphy.js`，可开关。
- **教训**：全卷 56531px 宽对移动端不友好（我们是虹桥段，尺寸策略更优）。

### 2.2 juicyzhou 汴京漫游 — 玩法系统最值得抄

- **程序化生成**：街道/店铺/虹桥/汴河/50 余人物全部代码生成，零外部资源，GH Pages 直接跑 —— 说明「无 3D 资产也能做出可玩的城」。
- **任务线**：8 条任务（送干粮、买茶叶、寻说书人、采药草、节奏撑船、城门传话、码头送布、糖人招客），完成得**铜钱 + 声望**，`J` 键看画卷成就 —— 把「逛」变成「玩」的核心机制。
- **反馈层**：小地图实时显示人与任务、头顶名牌、Web Audio 实时合成五声拨弦 BGM（不占音频文件体积）。
- **移动端**：左摇杆 + 右拖视角 + 圆形按钮；触屏自动降渲染档位。

### 2.3 pakho2433 — 「自动導覽 + 自由游览」双模式

- 电影式自动巡览（镜头自己走）+ 手动自由游览可随时接管/暂停 —— 解决「用户不知道往哪看」的最低成本方案。
- 程序生成的水面/船/人物动画让静态场景「活」起来；移动端三档画质开关。

### 2.4 appergb 繁花传薪 — 游戏化 + 轻后端范式

- WebGPU 光学解谜塔防，「以光修复名画」把修复叙事做成玩法（清明上河图是其中一张关卡画）。
- 后端极轻：Node + SQLite，**匿名游客**免登录、成绩上传、按关排行榜、公益（小红花）统计；后端不可达时前端完整可玩、联网功能静默隐藏 —— 若我们将来要上线上玩法/排行，这是最简参考架构。
- 部署注意：WebGPU 仅 HTTPS 可用（纯 HTTP 黑屏）。

### 2.5 Cecilia991 赛博千里江山图 — AI 时代的「名画 + 交互」新范式

- 粒子化重绘名画 + **摄像头手势**（单手张合）控制粒子群 —— 无需任何 3D 资产即可做出「可分享」的视觉奇观。
- 97 stars 说明这类「AI 生成 + 轻交互」装置在传播上有效；但其代码为 Gemini 生成且**明确禁商用**，只能参考思路。
- 迁移到我们：水墨粒子转场 / 开场粒子聚合成虹桥，作为可选增强层（WebGL/WebGPU，降级到静态图）。

### 2.6 LittleWhitechun — 声画联动（低成本高氛围）

- 浏览长卷时，**镜头经过某区域即播放该区域音效**（船声/叫卖/市声）+ 自动滚屏。
- 对我们几乎是「白捡」：CameraRig 已知相机 x 位置，四区（汴河水路/虹桥/桥头市集/南岸巷陌）→ 四段环境音交叉淡入淡出，Web Audio 即可。
